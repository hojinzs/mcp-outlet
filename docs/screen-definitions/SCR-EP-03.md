# SCR-EP-03 엔드포인트 상세

| 항목     | 내용                                                  |
| -------- | ----------------------------------------------------- |
| 경로     | `/admin/endpoints/:id`                                |
| 권한     | 엔드포인트 소유자 (admin도 다른 사람 것은 볼 수 없음) |
| 우선순위 | P0                                                    |
| 요구사항 | F-CON-04, F-CON-05, F-EP-02, F-EP-03, F-EP-04         |

## 목적

엔드포인트 하나의 노출 툴, 이름, 활성 상태를 바꾸고, 필요 없으면 지운다. 이 엔드포인트가 쓰는 커넥터의 자격증명도 여기서 고친다. 커넥터만 따로 관리하는 화면은 두지 않는다.

## 구성

### 머리

| 요소      | 내용                                         |
| --------- | -------------------------------------------- |
| 이름      | 연필 버튼으로 그 자리에서 편집. Enter로 저장 |
| 상태 배지 | SCR-EP-01의 상태 규칙과 같음                 |
| 연결 안내 | SCR-EP-04로 이동                             |

### 기본 정보

| 항목           | 내용                                                                    |
| -------------- | ----------------------------------------------------------------------- |
| 엔드포인트 URL | 전체 주소와 복사 버튼                                                   |
| 커넥터         | 커넥터 이름과 종류. 엔드포인트를 만든 뒤에는 다른 커넥터로 바꿀 수 없다 |
| 만든 날        | 날짜·시각                                                               |

### 커넥터 설정

이 엔드포인트가 쓰는 커넥터의 설정이다. 같은 커넥터를 쓰는 엔드포인트가 여러 개면 위에 "이 커넥터를 쓰는 엔드포인트 N개에 함께 적용됩니다"를 표시한다.

| 요소                           | 원격 MCP 서버                                                                                           | 내장 서비스                                                                                                         |
| ------------------------------ | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 주소·서비스                    | 커넥터 주소(편집 가능)                                                                                  | 서비스 이름(바꿀 수 없음)                                                                                           |
| 자격증명                       | 토큰: "설정됨 · {변경 시각}"과 교체 버튼                                                                | 연결된 계정(예: `steve@daniworks.kr`)·연결 시각, 다시 연결·다른 계정으로 바꾸기. 서비스 계정이면 이메일과 파일 교체 |
| 연결 테스트                    | 버튼과 "마지막 연결 테스트: {시각} · {결과 문구}"(테스트한 적이 없으면 "없음"). 성공하면 툴 목록을 갱신 | 같음                                                                                                                |
| 이 커넥터로 엔드포인트 하나 더 | SCR-EP-02로 이동(`?connector={id}`)                                                                     | 같음                                                                                                                |

- "이 커넥터로 엔드포인트 하나 더"는 커넥터가 정상(`ok`)일 때만 링크로 보인다. 아니면 링크 대신 상태 사유(연결 중·커넥터 오류·재연결 필요·사용 중지)를 보여준다. 이 화면의 연결 테스트·다시 연결로 고치면 링크가 켜진다.
- 주소나 토큰을 바꾸면 저장 전에 연결 테스트를 다시 해야 한다. 실패하면 저장하지 않는다.
- 연결 테스트 실패 분류와 문구는 SCR-EP-02의 연결 테스트와 같다.
- 연결 테스트가 `timeout`·`upstream_error`·`permission_denied`로 실패하면 커넥터 상태는 바뀌지 않는다(PRD "커넥터 오류 상태의 범위"). 상태가 정상인데 마지막 결과가 실패면 결과를 경고색으로 보이고 "커넥터 상태는 바꾸지 않았습니다. 일시적인 장애이거나 권한 문제라 자격증명은 그대로 유효합니다."를 덧붙인다. 상태가 정상이 아니면 결과를 오류색으로만 보인다.
- 재연결은 SCR-EP-02의 계정 연결과 같은 업스트림 동의를 거친다. 돌아오면 이 화면으로 온다. Google은 동의 화면 전에 계정 선택 화면을 띄우므로(`prompt=consent select_account`) 버튼 하나("다시 연결·다른 계정으로 바꾸기")로 같은 계정 재연결과 계정 바꾸기를 함께 한다.
- 재연결 안내("재연결 필요" 배너와 다시 연결 버튼)는 OAuth 커넥터에만 보인다. 서비스 계정은 다시 연결할 것이 없고 키 파일을 바꿔야 한다.
- **서비스 계정 키 거부**: 서비스 계정 커넥터가 커넥터 오류이고 마지막 연결 테스트가 인증 실패(`auth_failed`)면 키가 거부된 것으로 보고, 커넥터 설정 위에 "서비스 계정 키가 거부되었습니다. 키가 폐기되었거나 손상되었을 수 있습니다. 키 파일을 교체하세요."와 "키 파일 교체" 버튼을 오류색으로 강조해 보인다. 이때는 자격증명 칸의 평소 "키 파일 교체" 버튼을 숨기고 이 버튼으로 교체한다. 키 거부를 재연결 필요로 남기던 이전 서비스 계정 커넥터(`reauth_required`)도 같은 안내를 쓴다(PRD "서비스 계정 키 거부").

### 노출 툴

SCR-EP-02 2단계와 같은 툴 선택 목록을 쓴다. 다른 점은 다음과 같다.

| 요소            | 내용                                                                                            |
| --------------- | ----------------------------------------------------------------------------------------------- |
| 새 툴           | 허용목록을 정한 뒤 커넥터에 생긴 툴은 목록 위에 "새 툴" 묶음으로 따로 보여준다. 선택 안 된 상태 |
| 새 툴 확인함    | 새 툴을 허용하지 않고 배지만 없앤다. 허용목록은 그대로 두고 `knownTools`만 갱신한다             |
| 사라진 툴       | 허용목록에 있지만 커넥터 툴 목록에 없는 이름. "커넥터에서 사라짐" 표시와 함께 목록 끝에 둔다    |
| 저장 / 되돌리기 | 바뀐 것이 있을 때만 활성. 저장 전에는 호출에 반영되지 않는다                                    |

- 커넥터 툴 목록(툴 캐시)은 연결 테스트로 갱신되고, 원격 커넥터는 AI 클라이언트가 보낸 `tools/list`가 프록시를 지날 때도 갱신된다(PRD "툴 캐시 갱신"). 새 툴·사라진 툴은 이 목록 기준이다.
- 사라진 툴은 호출해도 업스트림이 거부하므로 해가 없다. 저장할 때 자동으로 빼지 않고, 허용목록에 있던 그대로 체크된 상태로 보여준다. 사용자가 체크를 풀고 저장하면 빠진다. 전체 선택·읽기 전용만·모두 해제는 커넥터 툴 목록에만 적용하고 사라진 툴의 체크는 바꾸지 않는다.
- 허용 툴을 0개로 저장할 수는 없다. 다 막고 싶으면 비활성을 쓰라고 안내한다.

### 상태

| 요소        | 내용                                                                             |
| ----------- | -------------------------------------------------------------------------------- |
| 활성 스위치 | 바꾸면 바로 저장한다. 다음 MCP 요청부터 반영(F-EP-04)                            |
| 설명        | 끄면 이 URL로 오는 요청을 거부합니다. AI 클라이언트의 연결 설정은 그대로 둡니다. |

### 최근 호출

이 엔드포인트로 들어온 툴 호출 최근 20건이다. 감사 로그(SCR-ADM-06)와 같은 기록에서 본인 엔드포인트 것만 보여준다.

| 열       | 내용                                                 |
| -------- | ---------------------------------------------------- |
| 시각     | 날짜·시각. 최신순                                    |
| 툴 이름  | 코드 글꼴                                            |
| 결과     | 성공 / 오류 / 거부 배지                              |
| 소요시간 | ms                                                   |
| 작업     | 허용목록 밖이라 거부된 툴이면 "허용목록에 추가" 버튼 |

- "허용목록에 추가"는 노출 툴 목록에서 그 툴을 체크한 상태로 바꾼다. 저장 버튼을 눌러야 반영된다.
- 호출이 없으면 "아직 호출이 없습니다. 연결 안내를 보고 AI 클라이언트에 등록하세요"와 연결 안내 링크를 보여준다.

### 삭제

화면 맨 아래 따로 둔다.

- 삭제 버튼을 누르면 확인 창을 띄운다. "삭제하면 이 주소로 다시 연결할 수 없습니다. 같은 설정이 필요하면 새로 만들어야 하고 주소도 바뀝니다."
- 이 커넥터를 쓰는 마지막 엔드포인트면 확인 창에 "커넥터와 자격증명도 함께 지우기"를 체크된 상태로 둔다. 체크를 풀면 커넥터를 남겨 두었다가 다시 쓸 수 있다. 정상 커넥터는 다음 엔드포인트 추가 때 "내 커넥터에서 고르기"로 고르고, 정상이 아닌 커넥터는 "엔드포인트 없는 커넥터"(SCR-EP-01)의 "다시 연결·연결 테스트"로 SCR-EP-02 이어하기 화면에서 고친 뒤 쓴다.
- 확인하면 지우고 목록(SCR-EP-01)으로 간다. 감사 로그의 기록은 남는다(엔드포인트 칸만 비워짐).

## 동작

- 저장하지 않은 툴 변경이 있는데 화면을 떠나면 확인을 띄운다.
- 다른 사람의 엔드포인트 ID로 들어오면 404로 처리한다. 존재 여부를 알려주지 않기 위해서다(F-AUTH-05).

## 결정 사항

- **새 툴 판별 (2026-11-04)**: `endpoints`에 `knownTools`(text[]) 컬럼을 추가한다. 허용목록을 저장하거나 "새 툴 확인함"을 누를 때 그 시점 커넥터의 툴 이름 전체를 저장한다. 새 툴은 `현재 커넥터 툴 − knownTools`다. 목록 화면(SCR-EP-01)의 "새 툴 N" 배지도 같은 값을 쓴다. 새 툴은 사용자가 허용하기 전에는 노출되지 않는다.
- **커넥터 삭제 (2026-11-05)**: 커넥터 설정 영역 맨 아래에 "커넥터 삭제"를 둔다(F-CON-04). 확인 창에 함께 지워질 엔드포인트 이름을 모두 보여주고, 확인하면 `DELETE /api/connectors/:id`로 커넥터·자격증명·엔드포인트를 함께 지운 뒤 목록(SCR-EP-01)으로 간다. 엔드포인트 삭제 때 커넥터를 남겨 둔 경우는 SCR-EP-01의 "엔드포인트 없는 커넥터"에서 지운다.
- **재연결 확인 (2026-11-05)**: 재연결(업스트림 동의) 콜백은 토큰을 저장한 뒤 연결 테스트(내장 커넥터의 권한 확인 `checkAccess`)를 통과해야 상태를 `ok`로 바꾼다. 실패하면 `connect_error=test_failed`로 돌아와 "계정은 연결했지만 연결 테스트에 실패했습니다"를 보여준다. 처음 연결(연결 중)은 SCR-EP-02의 연결 테스트가 맡는다.
