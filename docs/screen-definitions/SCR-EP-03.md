# SCR-EP-03 엔드포인트 상세·편집

| 항목     | 내용                                                  |
| -------- | ----------------------------------------------------- |
| 경로     | `/admin/endpoints/:id`                                |
| 권한     | 엔드포인트 소유자 (admin도 다른 사람 것은 볼 수 없음) |
| 우선순위 | P0                                                    |
| 요구사항 | F-EP-02, F-EP-03, F-EP-04                             |

## 목적

엔드포인트 하나의 노출 툴, 이름, 활성 상태를 바꾸고, 필요 없으면 지운다.

## 구성

### 머리

| 요소      | 내용                                         |
| --------- | -------------------------------------------- |
| 이름      | 연필 버튼으로 그 자리에서 편집. Enter로 저장 |
| 상태 배지 | SCR-EP-01의 상태 규칙과 같음                 |
| 연결 안내 | SCR-EP-04로 이동                             |

### 기본 정보

| 항목    | 내용                                                      |
| ------- | --------------------------------------------------------- |
| URL     | 전체 주소와 복사 버튼                                     |
| 커넥터  | 이름과 런타임 배지. 엔드포인트를 만든 뒤에는 바꿀 수 없다 |
| 만든 날 | 날짜·시각                                                 |

### 노출 툴

SCR-EP-02 2단계와 같은 툴 선택 목록을 쓴다. 다른 점은 다음과 같다.

| 요소            | 내용                                                                                            |
| --------------- | ----------------------------------------------------------------------------------------------- |
| 새 툴           | 허용목록을 정한 뒤 커넥터에 생긴 툴은 목록 위에 "새 툴" 묶음으로 따로 보여준다. 선택 안 된 상태 |
| 사라진 툴       | 허용목록에 있지만 커넥터 툴 목록에 없는 이름. "커넥터에서 사라짐" 표시와 함께 목록 끝에 둔다    |
| 저장 / 되돌리기 | 바뀐 것이 있을 때만 활성. 저장 전에는 호출에 반영되지 않는다                                    |

- 사라진 툴은 호출해도 업스트림이 거부하므로 해가 없다. 저장할 때 자동으로 빼지 않고, 사용자가 지울 수 있게 체크를 풀어 둔 상태로 보여준다.
- 허용 툴을 0개로 저장할 수는 없다. 다 막고 싶으면 비활성을 쓰라고 안내한다.

### 상태

| 요소        | 내용                                                                             |
| ----------- | -------------------------------------------------------------------------------- |
| 활성 스위치 | 바꾸면 바로 저장한다. 다음 MCP 요청부터 반영(F-EP-04)                            |
| 설명        | 끄면 이 URL로 오는 요청을 거부합니다. AI 클라이언트의 연결 설정은 그대로 둡니다. |

### 삭제

화면 맨 아래 따로 둔다.

- 삭제 버튼을 누르면 확인 창을 띄운다. "삭제하면 이 URL로 다시 연결할 수 없습니다. 같은 설정이 필요하면 새로 만들어야 하고 URL도 바뀝니다."
- 확인하면 지우고 목록(SCR-EP-01)으로 간다. 감사 로그의 기록은 남는다(엔드포인트 칸만 비워짐).

## 동작

- 저장하지 않은 툴 변경이 있는데 화면을 떠나면 확인을 띄운다.
- 다른 사람의 엔드포인트 ID로 들어오면 404로 처리한다. 존재 여부를 알려주지 않기 위해서다(F-AUTH-05).

## 필요한 API (안)

| 메서드 | 경로                 | 내용                                              |
| ------ | -------------------- | ------------------------------------------------- |
| GET    | `/api/endpoints/:id` | 엔드포인트와 커넥터 툴 목록, 새 툴·사라진 툴 구분 |
| PATCH  | `/api/endpoints/:id` | `name`, `allowedTools`, `enabled` 중 바꾼 것만    |
| DELETE | `/api/endpoints/:id` | 삭제                                              |

## 정할 것

- **새 툴 판별**: "새 툴"을 가리려면 허용목록을 저장할 때 커넥터에 어떤 툴이 있었는지 알아야 한다. 지금 `endpoints` 테이블에는 허용목록만 있다. 저장 시점의 툴 이름 목록(`knownTools`)을 같이 저장하는 컬럼을 추가해야 한다. 목록 화면(SCR-EP-01)의 "새 툴 N" 배지도 같은 값을 쓴다.
