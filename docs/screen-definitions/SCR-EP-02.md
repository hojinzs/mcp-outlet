# SCR-EP-02 엔드포인트 만들기

| 항목     | 내용                      |
| -------- | ------------------------- |
| 경로     | `/admin/endpoints/new`    |
| 권한     | user·admin                |
| 우선순위 | P0                        |
| 요구사항 | F-EP-01, F-EP-02, F-EP-03 |

## 목적

커넥터 하나를 고르고, 노출할 툴을 추려, AI 클라이언트에 붙일 URL을 만든다.

## 진입

- 엔드포인트 목록(SCR-EP-01)의 "새 엔드포인트"
- `?connector={id}`가 있으면 1단계를 건너뛰고 그 커넥터로 시작한다(커넥터 둘러보기 P1에서 사용).

## 구성

세 단계를 한 화면에서 순서대로 진행한다. 위쪽에 단계 표시(1 커넥터 → 2 툴 → 3 이름)를 두고, 지난 단계로는 언제든 돌아갈 수 있다.

### 1단계: 커넥터 선택

내가 볼 수 있는 커넥터를 카드로 보여준다. 전역 커넥터 중 공개 그룹에 내가 속한 것과 내 개인 커넥터다.

| 카드 요소   | 내용                                 |
| ----------- | ------------------------------------ |
| 이름·설명   | 매니페스트의 `name`, `description`   |
| 런타임 배지 | remote / builtin / stdio             |
| 툴 수       | 캐시된 툴 목록 기준                  |
| 상태        | 선택 가능 / 아래 표의 선택 불가 사유 |

| 선택 불가 사유     | 조건                                   | 안내                                         |
| ------------------ | -------------------------------------- | -------------------------------------------- |
| 툴 목록 없음       | 관리자가 연결 테스트를 아직 하지 않음  | 관리자가 커넥터 설정을 마치면 쓸 수 있습니다 |
| 자격증명 필요 (P1) | user 범위 자격증명 필드에 내 값이 없음 | 내 자격증명 입력 링크                        |

### 2단계: 노출 툴 선택

| 요소      | 내용                                                                                          |
| --------- | --------------------------------------------------------------------------------------------- |
| 일괄 선택 | 전체 선택 / 읽기 전용만 / 모두 해제                                                           |
| 검색      | 툴 이름·설명으로 거르기. 툴이 10개 이상일 때만 표시                                           |
| 툴 행     | 체크박스, 이름(코드 글꼴), 설명 첫 줄, 배지                                                   |
| 배지      | `readOnlyHint: true`면 "읽기", `destructiveHint: true`면 "삭제·변경". 힌트가 없으면 배지 없음 |
| 요약      | 하단에 "N개 선택"                                                                             |

- **읽기 전용만**은 `annotations.readOnlyHint === true`인 툴만 선택하고 나머지는 해제한다(F-EP-03). 힌트가 없는 툴은 읽기 전용으로 치지 않는다.
- 처음 들어오면 아무것도 선택하지 않은 상태다. 기본값을 "전체"로 두면 쓰기 툴이 실수로 노출될 수 있어서다.
- 한 개 이상 골라야 다음으로 넘어간다.

### 3단계: 이름

| 요소   | 내용                                                                              |
| ------ | --------------------------------------------------------------------------------- |
| 이름   | 기본값은 커넥터 이름. 같은 이름이 이미 있으면 뒤에 숫자를 붙여 제안(`Home CMS 2`) |
| 요약   | 커넥터, 선택한 툴 수, 읽기 전용이 아닌 툴이 있으면 그 수를 경고 색으로            |
| 만들기 | 저장 후 연결 안내(SCR-EP-04)로 이동                                               |

이름은 1~60자, 앞뒤 공백 제거. 내 엔드포인트끼리 같은 이름도 저장은 된다(URL이 따로 나오므로). 화면에서 숫자를 붙여 제안만 한다.

## 동작

- 단계 사이 이동은 화면 안에서만 하고, 만들기를 누르기 전에는 저장하지 않는다.
- 만드는 도중 이 화면을 떠나면 "만들던 내용이 사라집니다" 확인을 띄운다.
- 저장한 허용목록은 툴 이름 목록이다. 나중에 커넥터에 새 툴이 생겨도 자동으로 노출되지 않는다.

## 오류

| 경우                                    | 처리                                            |
| --------------------------------------- | ----------------------------------------------- |
| 저장 사이에 커넥터가 비공개로 바뀜      | "이 커넥터를 더 이상 쓸 수 없습니다" 후 1단계로 |
| 허용목록에 커넥터에 없는 툴 이름이 있음 | 서버가 거부. 툴 목록을 다시 불러와 2단계로      |

## 필요한 API (안)

| 메서드 | 경로                        | 내용                                                         |
| ------ | --------------------------- | ------------------------------------------------------------ |
| GET    | `/api/connectors`           | 내가 볼 수 있는 커넥터와 선택 가능 여부                      |
| GET    | `/api/connectors/:id/tools` | 캐시된 툴 목록(이름·설명·annotations)                        |
| POST   | `/api/endpoints`            | `{ connectorId, name, allowedTools }`. 서버가 툴 이름을 검증 |
