# SCR-EP-02 MCP 추가

| 항목     | 내용                                 |
| -------- | ------------------------------------ |
| 경로     | `/admin/endpoints/new`               |
| 권한     | user·admin                           |
| 우선순위 | P0 (원격 MCP 서버), P1 (내장 서비스) |
| 요구사항 | F-CON-01·02·03·05·06, F-EP-01·02·03  |

## 목적

사용자가 자기 MCP 서버나 내장 서비스를 등록하고, 노출할 툴을 골라, AI 에이전트에 붙일 MCP 주소를 받는다. 서버 등록과 첫 MCP 만들기를 한 흐름으로 끝낸다.

## 진입

- 내 MCP 목록(SCR-EP-01)의 "MCP 추가"
- MCP 상세(SCR-EP-03)의 "이 서버로 MCP 하나 더". `?connector={id}`로 들어와 1단계를 건너뛴다. 같은 서버로 읽기 전용·쓰기용 MCP를 나눌 때 쓴다.
- 내장 서비스 계정 연결(업스트림 동의) 뒤 돌아올 때. `?connector={id}&connected=1`로 1단계의 연결 테스트부터 이어간다.

## 구성

세 단계를 순서대로 진행한다. 위쪽에 단계 표시(1 서버 → 2 툴 → 3 이름)를 두고, 지난 단계로는 언제든 돌아갈 수 있다.

### 1단계: 서버

맨 위에서 둘 중 하나를 고른다. 내 서버가 하나도 없으면 "새 서버 등록"만 보인다.

| 선택               | 내용                                                                            |
| ------------------ | ------------------------------------------------------------------------------- |
| 내 서버에서 고르기 | 이미 등록한 서버 목록. 이름, 종류, 툴 수, 상태. 고르면 연결 테스트 없이 2단계로 |
| 새 서버 등록       | 종류를 고른다: 원격 MCP 서버 / 내장 서비스                                      |

#### 원격 MCP 서버 (P0)

| 필드      | 규칙                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------ |
| 서버 주소 | 필수. `https://`만. 원격 MCP의 Streamable HTTP 주소                                                    |
| 서버 이름 | 기본값은 주소의 호스트 이름. 1~60자                                                                    |
| 인증      | 없음 / 토큰. 기본값은 토큰                                                                             |
| 토큰      | 인증이 토큰일 때 필수. 비밀번호 입력란                                                                 |
| 고급      | 접어 둠. 헤더 이름(기본 `Authorization`), 접두어(기본 `Bearer `). 둘 다 비우면 토큰 값만 그대로 보낸다 |

#### 내장 서비스 (P1)

gateway에 들어 있는 내장 커넥터를 카드로 보여준다(예: Google Analytics 4 + Search Console, 채널톡). 고르면 그 서비스가 정한 접속 방식이 나온다.

| 접속 방식         | 화면                                                                                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 토큰              | 토큰 입력란 하나                                                                                                                                       |
| 서비스 계정 JSON  | 파일 선택. 서비스 계정 이메일을 보여주고 "이 계정에 GA 속성 보기 권한을 주세요" 안내                                                                   |
| 계정 연결 (OAuth) | ① 내 OAuth 앱 등록 안내와 **리디렉션 URI** `{PUBLIC_BASE_URL}/auth/upstream/callback`(복사 버튼) ② Client ID·Client Secret 입력 ③ "Google로 연결" 버튼 |

- 한 서비스에 방식이 여러 개면 탭으로 고른다. GA4는 서비스 계정을 먼저 보여준다. 사용자가 만든 외부(External) OAuth 앱이 테스트 상태면 refresh token이 7일에 만료되기 때문이다. OAuth 탭에는 "Workspace 내부 앱으로 만들거나 앱을 게시하세요" 안내를 둔다.
- **계정 연결 순서**: "Google로 연결"을 누르면 서버를 "연결 중" 상태로 먼저 저장하고 업스트림 동의 화면으로 보낸다. 돌아오면 이 화면의 연결 테스트로 이어간다. 저장하지 않으면 받은 refresh token을 둘 곳이 없어서다. 24시간 안에 MCP를 만들지 않은 "연결 중" 서버는 지운다.

#### 연결 테스트

1단계 맨 아래 "연결 테스트" 버튼. 성공해야 다음으로 넘어간다(F-CON-05).

- 업스트림에 `tools/list`를 보내 툴 목록을 받는다. 성공하면 "툴 N개를 찾았습니다"를 띄우고 다음 버튼을 켠다.
- 테스트할 때 보낸 토큰은 저장하지 않는다. 저장은 3단계의 만들기에서 한다.
- 실패하면 분류만 보여준다. 업스트림 응답 본문과 예외 원문은 보여주지 않는다(F-RUN-03).

| 실패 분류             | 문구                                                                        |
| --------------------- | --------------------------------------------------------------------------- |
| 내부망 주소           | 내부망 주소는 등록할 수 없습니다. 인터넷에서 접근할 수 있는 주소를 넣으세요 |
| 주소에 연결할 수 없음 | 서버에 연결하지 못했습니다. 주소를 확인하세요                               |
| 인증 실패 (401·403)   | 서버가 토큰을 거부했습니다. 토큰과 헤더 설정을 확인하세요                   |
| MCP 응답이 아님       | 이 주소에서 MCP 응답을 받지 못했습니다. MCP 서버 주소가 맞는지 확인하세요   |
| 시간 초과             | 서버 응답이 너무 늦습니다. 잠시 후 다시 시도하세요                          |
| redirect              | 서버가 다른 주소로 보냈습니다. 최종 주소를 직접 넣으세요                    |

내부망 주소 판정(F-CON-06): 주소의 호스트를 DNS로 해석해 사설(10/8, 172.16/12, 192.168/16)·loopback·link-local·클라우드 메타데이터(169.254.169.254) 대역이면 거부한다. 테스트할 때와 실제 호출할 때 모두 다시 해석한다.

### 2단계: 노출 툴 선택

| 요소      | 내용                                                                                          |
| --------- | --------------------------------------------------------------------------------------------- |
| 일괄 선택 | 전체 선택 / 읽기 전용만 / 모두 해제                                                           |
| 검색      | 툴 이름·설명으로 거르기. 툴이 10개 이상일 때만 표시                                           |
| 툴 행     | 체크박스, 이름(코드 글꼴), 설명 첫 줄, 배지                                                   |
| 배지      | `readOnlyHint: true`면 "읽기", `destructiveHint: true`면 "삭제·변경". 힌트가 없으면 배지 없음 |
| 요약      | 하단에 "N개 선택"                                                                             |

- **읽기 전용만**은 `annotations.readOnlyHint === true`인 툴만 선택하고 나머지는 해제한다(F-EP-03). 힌트가 없는 툴은 읽기 전용으로 치지 않는다.
- 처음 들어오면 아무것도 선택하지 않은 상태다. 기본값을 "전체"로 두면 쓰기 툴이 실수로 노출될 수 있어서다.
- 한 개 이상 골라야 다음으로 넘어간다.

### 3단계: 이름

| 요소   | 내용                                                                                  |
| ------ | ------------------------------------------------------------------------------------- |
| 이름   | 기본값은 서버 이름. 같은 이름의 MCP가 이미 있으면 뒤에 숫자를 붙여 제안(`Home CMS 2`) |
| 요약   | 서버, 선택한 툴 수, 읽기 전용이 아닌 툴이 있으면 그 수를 경고 색으로                  |
| 만들기 | 새 서버면 서버와 MCP를 함께 저장한다. 저장 후 연결 안내(SCR-EP-04)로 이동             |

이름은 1~60자, 앞뒤 공백 제거. 같은 이름도 저장은 된다(주소가 따로 나오므로). 화면에서 숫자를 붙여 제안만 한다.

## 동작

- 원격 MCP 서버는 만들기를 누를 때 서버와 MCP를 한 번에 저장한다. 중간에 떠나면 아무것도 남지 않는다.
- 내장 서비스의 계정 연결은 위 "계정 연결 순서"대로 서버를 먼저 저장한다.
- 만드는 도중 이 화면을 떠나면 "만들던 내용이 사라집니다" 확인을 띄운다.
- 저장한 허용목록은 툴 이름 목록이다. 나중에 서버에 새 툴이 생겨도 자동으로 노출되지 않는다. 저장할 때 그 시점 툴 이름 전체를 `knownTools`로 함께 저장한다.

## 오류

| 경우                            | 처리                                                                                    |
| ------------------------------- | --------------------------------------------------------------------------------------- |
| 저장 직전에 서버 툴 목록이 바뀜 | 서버가 허용목록을 거부. 툴 목록을 다시 불러와 2단계로                                   |
| 업스트림 동의를 취소함          | 1단계로 돌아와 "계정 연결을 취소했습니다"                                               |
| 업스트림 동의 후 토큰 교환 실패 | 1단계로 돌아와 "계정 연결에 실패했습니다. Client ID·Secret과 리디렉션 URI를 확인하세요" |

## 필요한 API (안)

| 메서드 | 경로                              | 내용                                                                                                                |
| ------ | --------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| GET    | `/api/connectors`                 | 내 서버 목록. 종류, 툴 수, 상태                                                                                     |
| GET    | `/api/builtins`                   | 내장 서비스 목록과 서비스별 접속 방식·입력 항목, 리디렉션 URI                                                       |
| POST   | `/api/connectors/test`            | 저장하지 않은 원격 서버 설정으로 연결 테스트. 내부망 주소 검사 포함. 토큰을 저장·기록하지 않음                      |
| POST   | `/api/connectors`                 | 내장 서비스 서버를 "연결 중"으로 저장(계정 연결 전)                                                                 |
| POST   | `/api/connectors/:id/oauth/start` | 업스트림 동의 주소를 만든다(state·PKCE 포함)                                                                        |
| GET    | `/auth/upstream/callback`         | gateway가 코드를 토큰으로 교환해 암호화 저장하고 이 화면으로 돌려보낸다                                             |
| POST   | `/api/connectors/:id/test`        | 저장된 서버로 연결 테스트하고 툴 목록 캐시 갱신                                                                     |
| GET    | `/api/connectors/:id/tools`       | 캐시된 툴 목록(이름·설명·annotations)                                                                               |
| POST   | `/api/endpoints`                  | `{ connectorId \| connector, name, allowedTools }`. 새 원격 서버면 `connector`로 서버 설정을 함께 보내 한 번에 저장 |
