# 요구사항 추적표 (v1)

[PRD v0.2](PRD.md)의 요구사항 ID마다 구현 위치와 그것을 확인하는 자동 테스트를 적는다. 경로는 레포 기준이고, gateway 경로의 앞 `apps/gateway/src/`는 줄여 `gw/`로 쓴다. 테스트는 `파일 › 테스트 이름`이다. 화면은 [화면 정의](screen-definitions/index.md)의 ID로 함께 적는다.

2026-11-06 기준 (M12). "자동 테스트 없음"은 실기 확인만 한 항목이고 근거를 함께 적는다.

## 남은 차이

M8(2026-11-05)에 spec-checker 점검의 사소 결함을 고쳤다: IdP 로그아웃 미지원 시 "다른 계정으로 로그인" 숨김과 안내(SCR-COM-03), 레이아웃 재연결 배지(SCR-COM-01), 내장 커넥터 툴 호출의 Google 401 → 커넥터 오류(M9에서 403은 툴 결과로 바꿈), 첫 연결 테스트 실패 커넥터를 연결 중으로 유지, 허용목록 판정 결과를 직렬화해 전달(중복 키 우회 방지), AES-GCM 태그 16바이트 고정, MCP Bearer의 id_token 거부(scope 클레임), Google 계정 선택 화면. M9(2026-11-05)에 재점검 결과를 반영했다: 툴 호출의 Google 403은 커넥터 상태를 바꾸지 않고 `permission_denied` 툴 결과로 돌려준다(401만 커넥터 오류), 내 커넥터에서 고르기는 정상 커넥터만 고르고 나머지는 상세나 "엔드포인트 없는 커넥터"로 안내(SCR-EP-02), `/auth/options` 실패 시 IdP 직접 로그아웃 안내(SCR-COM-03, `lib/session.ts` `accountSwitchMode`), 빈 `scp` 배열 거부(F-AUTH-03). M10(2026-11-05)에 남은 사소 결함을 고쳤다: 정상이 아닌 커넥터는 `?connector={id}`로 들어와도 툴 선택으로 건너뛰지 않고 SCR-EP-02 이어하기 화면(다시 연결·연결 테스트, 성공 시 2단계)으로 보내고, 엔드포인트 없는 커넥터의 링크도 그 화면으로(SCR-EP-01·02), SCR-EP-03 "하나 더"는 정상일 때만, 엔드포인트 없는 커넥터에 상태 배지, 엔드포인트 목록을 받기 전에는 상세 링크를 그리지 않음, builtin 툴 결과가 isError면 커넥터를 정상으로 되돌리지 않음. M11(2026-11-05)에 이어하기 화면을 마무리했다: 연결 테스트에 성공하면 이전 사유를 지우고(`resumeReason`), 엔드포인트 없는 커넥터도 그 화면에서 원격 접속 정보와 서비스 계정 키를 바꿀 수 있다(F-CON-04, SCR-EP-03의 `RemoteForm`·`ServiceAccountKeyPanel` 재사용). M12(2026-11-06)에 고쳤다: 업스트림 JSON 본문이 중간에 끊기면 MCP 오류로 답하고 감사 로그에 error로 남김(F-RUN-03), 감사 로그 툴 이름 200자·거부 행 요청당 20개(F-UI-03), 리소스·프롬프트·completion 차단(F-EP-02), groups 클레임이 없는 access token은 저장된 groups로 판정(F-AUTH-06), 로그인 scope `OIDC_SCOPES`(설정), `tools/call` 실패를 `isError` 툴 결과로(F-RUN-03), 커넥터 오류는 인증·연결 실패만(F-CON-05), SCR-EP-03 마지막 연결 테스트 결과와 상태를 두는 이유 표시, 프록시를 지나는 `tools/list`로 툴 캐시 갱신, 내장 커넥터 테스트 헬퍼의 감사 로그 순서(병렬 실행 flake). 남은 차이는 다음과 같다.

- **그룹에서 뺀 직후의 남은 시간** (F-AUTH-06): IdP에서 로그인 그룹을 빼도 이미 발급된 access token(groups 클레임에 그 그룹이 있음)은 만료(기본 30분)까지 MCP 호출에 쓰이고, 관리 UI 세션은 그 사람이 다시 로그인하거나 MCP 요청으로 거부되기 전까지 `SESSION_TTL_HOURS`(기본 12시간)까지 남는다. 관리자 그룹에서만 빠진 경우의 admin role도 같다. 즉시 끊으려면 DB `sessions`에서 그 사용자 행을 지운다(SCR-ADM-04 결정 사항, README). access token에 groups 클레임이 없는 IdP는 저장된 groups로 판정하므로 MCP 접근이 그 사용자가 관리 UI에 다시 로그인할 때까지 남는다(PRD "groups 클레임이 없는 access token"). dev Authentik은 앱 정책으로 토큰 발급 자체를 거부해("권한 거부됨") gateway의 groups 재확인과 접근 거부 화면(SCR-COM-03)까지 오지 않는다. gateway 쪽 거부는 자동 테스트로만 확인했다.
- **ChatGPT 실연결** (호환): Claude.ai와 MCP Inspector만 실기 확인했다.
- **Inspector v2의 목록 밖 호출** (F-EP-02 실기): MCP Inspector v2 웹 UI는 목록에 없는 툴 호출을 클라이언트에서 막는다. 목록 밖 호출 거부는 허용목록에서 뺀 뒤 이전 목록으로 호출해 확인했다(M7).
- **서비스 계정 키 폐기의 안내 문구** (SCR-EP-01·03, F-RUN-03): Google이 서비스 계정 assertion을 `invalid_grant`로 거부하면(키를 지움) `gw/upstream/oauth2.ts`가 OAuth refresh 거부와 같은 `invalid_grant`로 분류해 커넥터가 재연결 필요가 되고, 툴 결과와 화면이 OAuth용 "다시 연결" 문구를 보인다. 서비스 계정은 키 파일을 바꿔야 한다.
- **업스트림 OAuth state 쿠키 만료** (F-CON-03): 동의에 10분 넘게 걸려 state 쿠키가 만료되면 `gw/routes/upstream-auth.ts`가 `returnTo`를 알 수 없어 `/admin/?connect_error=failed`로 보내고, 홈(SCR-EP-01)은 `connect_error`를 읽지 않아 안내 없이 끝난다.
- **열린 스트림은 끊지 않음** (F-EP-04): 차이가 아니라 결정이다(PRD "열린 스트림"). 비활성·삭제·사용 중지·그룹 제거 뒤에도 이미 열린 SSE 스트림으로 시작된 호출의 결과와 알림은 나간다.
- **일괄 선택과 사라진 툴** (SCR-EP-03): "전체 선택"·"읽기 전용만"은 커넥터 툴 목록으로 선택을 새로 만들어(`apps/web/src/features/tools/selection.ts` `selectAll`·`selectReadOnly`) 사라진 툴의 체크도 푼다. SCR-EP-03의 "사라진 툴은 사용자가 체크를 풀어야 빠진다"와 다르다.
- **`limit_exceeded` 문구** (F-EP-01): 커넥터 상한과 엔드포인트 상한이 같은 문구("만들 수 있는 개수의 상한에 도달했습니다.")다. `details.resource`로 구분되지만 화면이 쓰지 않는다.
- **접근 거부 리디렉트의 이메일** (F-AUTH-06): 그룹 밖 로그인은 `/admin/forbidden?reason=not_member&email=…`로 보내(`gw/routes/auth.ts`) 이메일이 주소에 실린다(리버스 프록시 접근 로그·브라우저 기록).
- **상한 확인 경합** (F-EP-01): `assertConnectorQuota`·`assertEndpointQuota`는 센 뒤 넣으므로 같은 사용자의 동시 요청이 상한을 넘길 수 있다.
- **id 없는 tools/call** (F-UI-03): 허용목록 안의 `tools/call`을 id 없이(알림으로) 보내면 업스트림에는 가지만 응답이 없어 감사 로그에 남지 않는다. 목록 밖이면 거부와 함께 남는다.
- **재개 스트림의 tools/list** (툴 캐시): 차이가 아니라 결정이다(PRD "툴 캐시 갱신"). GET 스트림 재개로 온 `tools/list` 응답은 허용목록으로 거르기만 하고 캐시에는 쓰지 않는다.
